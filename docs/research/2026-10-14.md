## 1. Dependency advisories

**Affects rustkube**
- **rustls-webpki 0.103.9 (locked) — RUSTSEC-2026-0104**: reachable panic parsing a CRL (empty `onlySomeReasons` BIT STRING), before signature check. Fixed in >= 0.103.13. rustkube feeds operator CRLs to `WebPkiClientVerifier::with_crls` and re-reads them every 30 s (`--client-crl-file`, #260), so a bad CRL file can panic the reload path. https://rustsec.org/advisories/RUSTSEC-2026-0104.html (published April 2026, modified 2026-09-19, not new in the window but unfixed here)
- Same crate, **RUSTSEC-2026-0098 / 0099**: URI and wildcard-DNS name constraints ignored; need a misissued cert. Fixed in >= 0.103.12. https://rustsec.org/advisories/RUSTSEC-2026-0098.html , https://rustsec.org/advisories/RUSTSEC-2026-0099.html
- Filed: see issue linked below.

**In the lock file, probably not reachable**
- **quinn-proto 0.11.14 — RUSTSEC-2026-0338** (added 2026-10-12; 0339–0341 also added, details not read): remote panic on zero-length STREAM frames in unordered-read mode; fixed in >= 0.11.18. Pulled only through `reqwest` -> `quinn`; rustkube enables no HTTP/3 and opens no UDP/QUIC socket. Fixed by the same `cargo update`. https://rustsec.org/advisories/RUSTSEC-2026-0338.html

**Informational**
- **unsafe-libyaml 0.2.11 — RUSTSEC-2024-0449** (re-added 2026-10-12): unmaintained, no patch; reached through `serde_yaml 0.9` (itself deprecated), used in apimachinery and apiserver for YAML bodies (#122). Alternatives named: saphyr / serde-saphyr. Not filed (no vulnerability); worth a P3 when YAML handling is next touched. https://rustsec.org/advisories/RUSTSEC-2024-0449.html
- Other advisories added 2026-10-07..13 (wasapi, libcrux-*, noyalib, bip322, ammonia, ic-cipher, mykey, kuva, ruzstd) are for crates not in the lock file (not checked for ruzstd beyond name; not found in `Cargo.lock` grep of the checked names). Source: https://github.com/rustsec/advisory-db/commits/main/crates

Not covered: package.json (none), images pulled (none by this repo), Go-side Kubernetes CVEs (rustkube is not a Go consumer). Search found no RUSTSEC entry in the window for tokio, hyper, h2, axum, ring, etcd-client, tonic, prost, jsonwebtoken, rcgen, x509-parser; the advisory-db commit list was read by title only, so this is not a proof of absence.
